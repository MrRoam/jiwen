# 实例管理

本文供运行即问的维护者使用。配置存储和转写上限前，先确认设备容量和供应商限制。

## 本机控制台

Windows 双击项目根目录的 `打开控制台.cmd`，或运行 `npm run console`。默认地址为 `http://127.0.0.1:4319`。

控制台无需登录，仅监听本机回环地址。公网应用不提供控制台页面或管理接口。Docker 不发布控制台端口，容器内的回环地址不能直接从宿主机访问。

控制台可查看在线人数、录音和处理任务、每日用量、存储及 API 成本估算。页面每 5 秒更新，存储每 30 秒重新统计。在线人数按账号去重，失效连接约 60 秒内移出；近一小时趋势从本次服务启动后开始记录。

每日用量和成本统计在北京时间 08:00 切换。成本按实际转写时长、服务商返回的 Token 数和已配置单价估算，实际支付以服务商账单为准。赠送额度、优惠和本机资源开销不计入。

自动计价支持北京地域的 Fun-ASR 实时转写、Qwen3.7-Flash 及 OpenRouter 免费路由。缺少计价信息的记录显示为未计价。展开「计价说明」查看单价和来源。

成本记录不因关闭控制台、重启、删除课堂或账号而扣回。匿名计费记录保留 90 天。

控制台可重启应用。存在录音、待恢复录音、保存、回放、问答、连接测试或后台处理任务时，服务会拒绝重启。重启保留已保存的数据和额度，重新积累在线趋势；公网隧道和本机 Python 转写服务需另行管理。

`npm start`、`npm run dev`、Docker 和内测启动脚本默认启用控制台。直接运行 `server/index.js` 时需设置 `CONSOLE_PORT`，且只提供监控。修改 `.env` 中的 `CONSOLE_PORT` 可更改端口，设为 `0` 可禁用。

## 配置位置

| 位置 | 内容 |
| --- | --- |
| 页面「API 配置」 | 转写和问答服务的密钥、地址、模型及连接测试，仅管理员可修改 |
| 服务器 `.env` | 端口、管理员邮箱、邮件、额度、存储及可选功能 |
| `data/` | 私有 API 配置、SQLite 数据库和课堂录音 |

页面配置保存在 `data/service-config.json`，保存后立即生效，重启后保留。已保存字段优先于 `.env`。存在录音、保存、回答或连接测试任务时，不能修改 API 配置。

内测启动脚本关闭页面 API 配置，由维护者在服务器端管理；本机控制台仍可使用。

## 存储和保存期

以下是程序默认值，可在 `.env` 修改，重启后生效。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `USER_STORAGE_BYTES` | 524288000 | 每账号最多使用 500 MiB 服务器存储 |
| `GLOBAL_STORAGE_BYTES` | 107374182400 | 全部账号共用 100 GiB 服务器存储 |
| `MIN_FREE_DISK_BYTES` | 21474836480 | 保留 20 GiB 磁盘空闲空间 |
| `LESSON_RETENTION_DAYS` | 30 | 课堂保存天数 |
| `MAX_RECORDING_SECONDS` | 7200 | 单段录音最多 2 小时 |

每账号的存储上限计算该账号在服务器上保存的数据，不是转写时长。原始音频分段和回放副本都计入用量。容量不足时会限制新录音或上传；删除旧课堂可释放空间。MiB 和 GiB 是容量单位，分别等于 1024² 和 1024³ 字节。

课堂保存期从最后一次成功上传新音频分段起计算。浏览和提问不会延长保存期。到期后删除该课堂的录音、转写和对话；页面在到期前 7 天和 1 天提醒。账号可在「数据与反馈」下载资料或申请注销。

服务器单实例运行，数据库和录音保存在本地磁盘。不要同时启动使用同一数据库的服务。备份与恢复步骤见[服务器部署说明](../deploy/README.md#更新和备份)。

## 转写接入

`MAX_ASR_CONCURRENCY` 默认最多接入 50 路转写，包含等待启动的连接。`ASR_STARTS_PER_SECOND` 默认每秒最多启动 15 个云端任务，不限制已启动任务持续发送音频。

这些参数是程序上限，不能用来证明服务器可承载同等数量的课堂。部署前需在目标设备和服务配置下验证。账号额度见[账号与额度](账号与额度.md)，本机模型安装和后台补转写见[本地转写](本地转写.md)。

## 录音恢复

音频分段先保存在浏览器 IndexedDB，再按顺序上传；重试会去重。「恢复上传」逐条保存当前浏览器中属于该账号的录音，一条失败不影响其他录音。仍在其他页面录制的录音，需要先暂停并保存。

服务器生成回放后保留原始分段，用于合并迟到的补传内容。旧版本若已删除原始分段，补传内容和已有回放仍可保存，但可能无法合并出完整回放。

录音保存和转写独立。启用本机补转写服务后，录音保存完成时会尝试补齐缺失文字；未启用时不能保证补齐。
