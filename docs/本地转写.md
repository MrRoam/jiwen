# 本地转写与 GPU 评测

本地服务运行在应用服务器所在的机器。采用本地实时转写时，音频不发送到云端转写服务；问答仍按已配置的接口运行。安装和首次模型下载都由用户手动执行，不会随 `npm install` 自动发生。安装脚本使用独立 `.venv-asr`，不修改系统 Python，也不重启应用。

也可使用混合模式：`ASR_PROVIDER=remote` 让实时转写走云端，`LOCAL_ASR_RECOVERY=true` 单独启用本机后台补转写。补转写读取已保存录音，不再把整段录音发到云端重复计费；仍遵守账号与全站的音频额度。云实时模式下可与本机补写并行，后台最多处理一个任务；同一条录音尚在采集或保存时不能补写。本地实时模式仍保留全站实时录音优先。该开关默认关闭，启用后需要保持本地 Python 模型服务运行。内测启动脚本会按这个开关启动本地服务，隐私政策会同时显示云端实时转写和运营者本地补转写。

Windows 推荐使用安装脚本。保留原来的 CPU `small` 路线：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File scripts/setup-local-asr.ps1 -Engine whisper -Device cpu
.\.venv-asr\Scripts\python server/local_asr.py --engine whisper --model small --device cpu --compute int8
```

中文流式 GPU 路线：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File scripts/setup-local-asr.ps1 -Engine paraformer-streaming -Device cuda
.\.venv-asr\Scripts\python server/local_asr.py --engine paraformer-streaming --device cuda --max-streams 20
```

CUDA 版 PyTorch 及依赖需要数 GB 磁盘空间，流式模型约 0.9 GB；首次启动下载模型。安装脚本会实际运行设备探测，但设备探测成功仍不等于模型推理成功。CUDA/驱动不匹配时服务会明确启动失败，不会悄悄转到 CPU 并宣称 GPU 可用。

若 Python 的 HF 下载客户端无法使用本机的证书链，可用 PowerShell 在保持证书校验的条件下下载固定快照，再按本地目录启动，不要关闭 TLS 验证：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File scripts/setup-local-asr.ps1 -Engine paraformer-streaming -Device cuda -SkipInstall -DownloadModel
.\.venv-asr\Scripts\python server/local_asr.py --engine paraformer-streaming --device cuda --model-path output/local-asr-models/fd2af606b37d7fb8b3b8a218c5be5b07b53ef6ba
```

macOS/Linux：

```sh
python3 -m venv .venv-asr
.venv-asr/bin/python -m pip install -r server/requirements-local-asr.txt
.venv-asr/bin/python server/local_asr.py --engine whisper --device cpu
```

启动输出 `event: ready` 后，进入“侧栏底部账号 → API 配置”，选择本地转写，地址为 `http://127.0.0.1:4318`。Whisper 模型显示名称填 `small`；流式模型填 `funasr/paraformer-zh-streaming`。保存并测试连接会处理一秒静音，仅验证通路。页面名称不改变 Python 实际加载的模型。

Python 不自动读取 `.env`。可用命令行或进程环境变量设置参数，命令行优先：

| 参数 | 环境变量 | 默认值 |
| --- | --- | --- |
| `--engine` | `LOCAL_ASR_ENGINE` | `whisper` |
| `--device` | `LOCAL_ASR_DEVICE` | `cpu` |
| `--model`（Whisper） | `LOCAL_ASR_MODEL` | `small` |
| `--model-path`（固定流式模型目录） | `LOCAL_ASR_MODEL_PATH` | 为空，使用 HF 缓存 |
| `--compute`（Whisper） | `LOCAL_ASR_COMPUTE` | `int8` |
| `--port` | `LOCAL_ASR_PORT` | `4318` |
| `--max-streams` | `LOCAL_ASR_MAX_STREAMS` | `20` |
| `--max-jobs` | `LOCAL_ASR_MAX_JOBS` | `128` |
| `--max-queued-seconds` | `LOCAL_ASR_MAX_QUEUED_SECONDS` | `120` |
| `--max-wait-seconds` | `LOCAL_ASR_MAX_WAIT_SECONDS` | `60` |

这里的 `max-streams` 是服务接收上限，不能当作已验证容量；应用还有独立的全站转写并发上限。提高限额不能让 GPU 自动变快。

Whisper 每 10 秒提交一段，暂停时处理尾段。Paraformer 每 600 ms 提交一段，使用每录音独立的 cache 和递增序号，最后提交 `is_final` 刷新尾字。模型工作线程按有界 FIFO 排队；每路同时只有一个推理请求，健康检查使用独立接收线程。该实现没有跨用户 GPU 合批，也没有声称支持 100 路。

队列满、并发上限、排队超时都会明确失败，录音仍独立保存，不自动切换付费 API。浏览器尚未连接转写时只保留约5秒PCM，超出的内容会记录为缺口；应用到本地模型的待处理PCM上限为两分钟。

本地实时模式或 `LOCAL_ASR_RECOVERY=true` 时，录音保存后会把缺口加入后台补转写队列；没有文字的旧录音也可点击“补转写”。后台一次处理一段录音，实时录音优先，识别整段保存的音频以补齐缺字。成功后事务替换这段录音的文字；失败保留原文，已有对话的冻结快照保持不变。后台任务共用账号转写额度及全站日额度，已记账的同一录音时长不重复扣额。体验站一次性额度用尽后不再自动排队；月度或全站临时额度恢复后可重新排队。队列最多128个任务，满载时保留录音并提示重试。

Paraformer输出时间范围是分段近似值，不能用于精确逐字字幕或词级定位。

健康和容量状态可查看 `http://127.0.0.1:4318/health` 或 `/status`，包含真实 engine/device、分段大小、队列音频时长、最老任务等待时长、成功/失败/拒绝数。`ready` 表示服务已加载，不表示高并发已验收。

Paraformer 固定 HF 仓库 `funasr/paraformer-zh-streaming` 的许可快照 `apache-2.0-20260804`，代码固定 commit `fd2af606b37d7fb8b3b8a218c5be5b07b53ef6ba`；启动状态记录模型与 LICENSE 的 SHA-256。该快照将权重和附属文件明确纳入 Apache-2.0，不使用缺少许可文件的旧版本。[许可说明](https://huggingface.co/funasr/paraformer-zh-streaming/blob/apache-2.0-20260804/README.md)、[LICENSE](https://huggingface.co/funasr/paraformer-zh-streaming/blob/apache-2.0-20260804/LICENSE)。官方流式接口要求独立 cache、按序提交、尾段 final，并使用 `batch_size=1`。[官方用法](https://github.com/modelscope/FunASR/blob/main/docs/python_api.md)。

## 用实际音频测容量

准备已获授权的 16 kHz、单声道、16-bit PCM WAV；不要使用未经许可的课堂或个人录音。先单路验证，再运行开放环评测：

```powershell
.\.venv-asr\Scripts\python scripts/benchmark-local-asr.py --wav D:\测试音频\已授权课堂.wav --streams 1,5,10,20,50,100 --seconds 120 --output output/local-asr-benchmark.json
```

评测按墙钟产生音频分段，不等待上一条响应。每路发送线程保持原始顺序，因此慢模型会累积可见的客户端队列，而不会用降低发送速率掩盖过载。报告记录 P50/P95 端到端延迟（包括客户端积压）、服务排队、推理耗时、吞吐、失败流数、未完成任务和随时间变化的积压。达到有界缓存或服务容量后记录失败，取消缓存；有请求未结束时停止后续档位，防止结果混杂。

报告中的 `endToEnd` 从一段音频**采集完成**开始，到 HTTP 响应结束，包含空文本响应；它不含这段音频的 600 ms 采集时间，也不能当作首字延迟。`firstTextFromRecordingStart` 单独记录从测试流开始到第一次非空输出的时间，可能包含样本前导静音。

`--seconds` 是每路实时输入时长，音频不足时循环使用；总输入约为“并发数 × 时长”。短测和重复同一音频只能找容量问题。真实课堂验收应使用多种授权录音，并持续一节课及以上，检查延迟是否稳定、积压是否增长、GPU 显存是否稳定。8 GB 显存不等于足够 100 路，设备名称也不能代替这个评测。

若有与完整 WAV 对应的人工标注文本，可加 `--reference D:\测试音频\标注.txt`。程序会另跑整个音频并计算 CER，归一化规则为 NFKC、小写、去空白与标点。不提供标注时 CER 为 `null`，不虚构准确率。合成语音请加 `--sample-kind synthetic`，只用于通路验证；公开许可样本请加 `--sample-kind public-licensed`。报告默认不保存识别正文，也不记录私人音频路径。

调度层回归验证不依赖模型下载：

```powershell
node --test tests/local-asr.test.js
python tests/local-asr-python.test.py
python tests/local-asr-benchmark.test.py
```

Docker Compose 默认不包含此 Python 服务。Whisper GPU 运行仍需 CTranslate2 对应的 CUDA/cuDNN 运行库；安装 PyTorch 不保证这些动态库自动可见。依赖和硬件说明参见 [faster-whisper](https://github.com/SYSTRAN/faster-whisper)。

## 本机实测记录（2026-10-07）

RTX 5060 Laptop GPU，8 GB 显存，驱动 592.01；独立环境 Python 3.13.11、PyTorch 2.10.0+cu128、FunASR 1.4.16。GPU 张量运算、固定流式模型真实推理、Node 适配器的连续分段和空尾段刷新均已实际通过，模型参数设备为 `cuda:0`。模型 SHA-256 为 `4fdfb48ed4471777c9a511e96a2acae17f77cac9d709cc756634622769192a64`。

使用该许可快照的官方样例，每档每路只输入 **3.6 秒**，各档最后任务均完成、无 HTTP 失败。热模型阶梯结果保存在本机 `output/local-asr-gpu-ladder.json`，只说明本机现有实现的短时表现：

| 并发流数 | 分段采集完成至响应 P95 | 完成音频秒 / 墙钟秒 |
| --- | --- | --- |
| 1 | 169.2 ms | 0.955 |
| 5 | 296.9 ms | 4.537 |
| 10 | 508.5 ms | 8.349 |
| 20 | 1,658.8 ms | 12.674 |
| 50 | 8,497.2 ms | 13.674 |
| 100 | 21,935.6 ms | 12.888 |

**当前实现不能做 100 路实时转写。** 100 路持续输入要求每秒处理约 100 秒音频；本次 100 路的尾部延迟已达到约 24 秒，短输入最终完成不能证明实时可用。该结果也不能单独断言 GPU 硬件的最终上限：当前流式接口是 `batch_size=1`、单模型工作线程，继续优化需要另外的跨流调度/批处理实现与重新评测。

5 路可作为首轮公测的保守配置，但一节课的持续容量、真实课堂准确率、多人噪声与专业词汇仍未验收；不能宣传质量保证。样例没有配套人工标注，本次不报告 CER。测试使用独立临时端口，未更改或重启应用服务。
